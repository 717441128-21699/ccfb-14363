# 驿站 Utility AI 旅客行为系统

一个用 TypeScript + Canvas 实现的 Utility AI 群体行为模拟：驿站里的旅客有
**饥饿 / 疲劳 / 压力（=100−心情）/ 马饥饿 / 钱** 五类状态，每个决策时刻对
**吃饭、喝茶、喂马、住店、打听消息、吵架、闲逛** 七个候选行动打分，选综合效用最高的执行。

## 跑起来

```bash
npm install
npm run dev        # 浏览器打开调试台（默认 http://localhost:5173）
```

其它命令：

```bash
npm test           # 13 个逻辑单元测试（曲线/门控/兜底/日志/端到端模拟）
npm run bench      # 2000 NPC 决策性能基准 + 7 行动覆盖检查
npx tsx perf/coverage-sim.ts   # 自然演化 7.5 天，统计 7 个行动是否都会发生
npx tsx perf/smoke-sim.ts      # 多日长时模拟冒烟（数值合法性/无卡死/经济循环）
npm run build      # 类型检查 + 生产构建
```

## Utility 打分模型

每个行动由若干考虑项组成，决策流程：

```
考虑项原始输入 ──分段线性曲线──▶ 0~1 效用 ──加权平均──▶ ×性格亲和度 ──▶ 最终分
                                  │
                          硬门控失败直接归零（付不起钱 / 设施满员）
```

关键设计决策：

- **门控不参与加权平均**（`gateOnly`）。钱和空位是「约束」不是「动机」，
  若让恒为 1 的门控项进加权，会稀释真实需求分，导致 NPC 没需求时也乱花钱。
- **闲逛是兜底行动**。所有正经行动分数低于 `FALLBACK_THRESHOLD` 或被门控时选它，
  保证旅客永远不会站着不动。
- **性格做乘性亲和度修正**（节俭/好斗/健谈/尽责），让同状态的旅客有不同选择，
  并列时也靠它打破平局。
- **经济循环**：旅客每天跨午夜收到盘缠（70~110 文，节俭者略多），否则只花不赚
  会在一两天后全员破产。

## 性能（3ms 预算怎么守住的）

需求是「2000 NPC 同时在线，每帧决策总耗时 ≤ 3ms」。做法不是优化单次决策，
而是**让一帧根本不需要决策 2000 次**：

1. **错峰调度**：每个 NPC 有自己的 `nextDecideAt`，首次决策均匀打散，
   行动结束后才安排下一次重估。基准实测单帧最多 ~97 人到期决策。
2. **热路径零分配**：打分明细写进 NPC 构造时预分配的 `Float32Array/Uint8Array`，
   上下文对象复用，决策过程不 new 任何对象，避免 GC 抖动。
3. **曲线二分求值**：控制点只有 2~5 个，O(log n) 几乎免费。

`npm run bench` 实测（本机）：全量决策 2000 人一轮约 1.8ms（最坏上界），
真实错峰帧决策阶段峰值约 2.1ms，3000 帧里 0 帧超 3ms。页面 HUD 实时显示
本帧决策耗时与「达标/超预算」徽章。

## 调试页能做什么

- **点任意旅客**：右侧显示四项需求条、性格、当前状态，以及**七个候选行动的完整打分明细**
  （每个考虑项的原始输入 → 曲线效用、门控通过/拦截、最终分），高亮本次选中的行动和入选原因。
- **拖曲线即时生效**：下拉选曲线，拖拽控制点改 y（Shift+拖改 x），双击空白加点、
  双击点删除。改动立即让空闲 NPC 按新曲线重估，并自动存 localStorage。
- **导出/导入曲线 JSON**、一键恢复默认。
- **导出单个旅客的全天决策记录**：CSV（Excel 直接打开）或 JSON，每条含决策时刻、
  选中行动、得分、原因、四项需求、剩余钱、设施空位。
- **模拟控制**：暂停、1×/4×/8×/20× 速度、常规 45 人 / 压测 2000 人一键切换。

## 美术可读性

- 旅客圆点颜色随当前行动变化，**头顶气泡**显示正在做/最想做的事（图标+中文名）。
- 饥饿 ≥85 的旅客有**红色描边**，且移速经 `speed.hunger` 曲线明显下降
  （满饥饿时移速降到 45%），玩家能直接看出「这人快饿晕了」。
- 2000 人压测时气泡抽样显示（始终保留选中者），避免画面糊成一团。

## 策划调曲线指引

所有曲线都是 `src/core/config.ts` 里的分段线性点，也可以在调试页直接拖。
一个容易踩的坑：**曲线甜区不能比决策粒度还窄**。NPC 两次决策之间压力可能跳 50~80
点（行动期间不重估），把某行动的有效窗口设成 65~80 这种窄段，它在离散决策下
几乎永远落不进去。调试时用 `perf/coverage-sim.ts` 验证每个行动在自然演化里真的会发生。
